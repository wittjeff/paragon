There are currently two built-in options for displaying the data `DataTable.Table` and `CardView`, but you can also build your own.

## DataTable.Table

The `Table` component is meant to be rendered within a `DataTableContext` (provided by `DataTable` here).
It displays the data provided by the `DataTableContext` as an html table.

## Table Subcomponents

Subcomponents of `DataTable.Table` can be used independently of the main component. They are designed for use with a `react-table` instance.

See the available props of `<TableRow>`, `<TableCell>`, `<TableHeaderCell>`, and `<TableHeaderRow>` below.

## CardView and alternate table components

You may choose to use any table component by using the following code in your display component:
```jsx
const instance = useContext(DataTableContext)
```

### Sample Card component for use with CardView

The `CardComponent` prop on `CardView` represents a table row, and will receive the row that `react-table`
provides as props.

```jsx
const MiyazakiCard = ({ className, original  }) => {
  const { title, director, release_date } = original;

  return (
    <Card className={className}>
      <Card.ImageCap src="https://picsum.photos/360/200/" srcAlt="Card image" />
      <Card.Section title={title}>
        <dl>
          <dt>Director</dt><dd>{director}</dd>
          <dt>Release Date</dt><dd>{release_date}</dd>
        </dl>
      </Card.Section>
    </Card>
  );
};
```

## Accessibility

**Status:** documented from source (Paragon 23.x, August 2026). Assistive technology verification pending — see the [Accessibility policy](/guides/accessibility-policy).

`DataTable.Table` renders a native HTML table; its semantics, keyboard behavior, and known issues are documented in the [main DataTable Accessibility section](/components/datatable/#accessibility). This section covers what changes in `CardView`. No APG pattern applies to a card grid; it is plain document content.

### Keyboard support

`CardView` adds no keyboard behavior of its own. Focus moves through whatever interactive elements your `CardComponent` renders, plus the selection checkbox next to each card when `isSelectable` is set. The surrounding filter, action, and pagination controls behave as in table view.

### ARIA roles, states, and properties

| Element | Attribute | Notes |
| --- | --- | --- |
| Card grid (`CardGrid`) | *(no role)* | A `div`-based responsive grid — no table, list, or grid semantics. Reading order is DOM order. |
| Card | consumer-provided | `CardView` renders your `CardComponent` per row; its semantics are yours. |
| Selection checkbox | `<input type="checkbox" title="Toggle Row Selected">` | The same selection component as table view; named only by react-table's default `title` (see the main page's Known issues). |
| Loading state | *(no role)* | Skeleton cards replace content while `isLoading` is set; the swap is not announced. |

### Screen reader expectations

- Cards read as ordinary page content in DOM order — there is no "x of y" item context, because the grid has no list semantics. *(Verification pending per the policy's AT matrix.)*
- A card's selection checkbox announces as "Toggle Row Selected, checkbox", with nothing tying it to the card it selects. *(Verification pending per the policy's AT matrix.)*

### Application responsibilities

- All row context lives in your `CardComponent`: include the fields a table row would have shown, and start each card with a heading (e.g. `Card.Header` `title`) so screen reader users can navigate card to card by heading.
- Give images in cards meaningful `alt`/`srcAlt` text, or empty alternatives when decorative.
- If cards are selectable, keep the primary identifying text adjacent to the checkbox in DOM order to mitigate the generic checkbox name.
- When using the card/list view toggle, note that view switches are not announced (see [TableControlBar](/components/datatable/tablecontrolbar#accessibility)).

### Relevant ACT rules

[W3C Accessibility Conformance Testing rules](https://www.w3.org/WAI/standards-guidelines/act/rules/)
give objective, tool-neutral procedures for testing the claims above:

- [Form field has non-empty accessible name](https://www.w3.org/WAI/standards-guidelines/act/rules/e086e5/) — card selection checkboxes
- [Image has non-empty accessible name](https://www.w3.org/WAI/standards-guidelines/act/rules/23a2a8/) — card images
- [Element in sequential focus order has visible focus](https://www.w3.org/WAI/standards-guidelines/act/rules/oj04fd/)

### Known issues

Identified in the August 2026 accessibility audit:

- Card collections have no list semantics (plain `div` grid), so assistive technology gets no item count or position when browsing cards.
- Card selection checkboxes share the table view's generic, unlocalized `title`-based name ("Toggle Row Selected") and are not programmatically associated with their card — tracked with the selection naming issue on the [main DataTable page](/components/datatable/#known-issues).
