A form control renders a space for user input (`input` or `select`). It can be
decorated with leading or trailing elements, and have a floating label.

Prefer to use the Form.Control component inside a `Form.Group`. The `Form.Group`
provides a context for the control to ensure accessibility requirements for
labels and descriptions are met.

Note: extra props added to this component are passed as attributes to the
underlying DOM node (`input` by default). See MDN for documentation on available
[input attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attributes)
or [select attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/select#attributes).

## Usage with decorators and floating label

```jsx live
() => {
  const [value, setValue] = useState('');
  return (
    <Form.Group>
      <Form.Control
        leadingElement={<Icon src={FavoriteBorder} />}
        trailingElement={<Icon src={Verified} />}
        floatingLabel="What kind of cats?"
        value={value}
        onChange={(e) => setValue(e.target.value)}
      />
    </Form.Group>
  );
}
```

## Input masks
Paragon uses the [react-imask](https://www.npmjs.com/package/react-imask) library,
which allows you to add masks of different types for inputs.
To create your own mask, you need to pass the required mask pattern (`+{1} (000) 000-0000`) to the `inputMask` property. <br />
See [react-imask](https://imask.js.org) for documentation on available props.

```jsx live
() => {
  {/* start example state */}
  const [maskType, setMaskType] = useState('phone');
  const [value, setValue] = useState('');
  {/* end example state */}
  const handleChange = (e) => setValue(e.target.value);

  const inputsWithMask = {
    phone: (
      <>
        <h3>Phone</h3>
        <Form.Group>
          <Form.Control
            inputMask="+{1} (000) 000-0000"
            value={value}
            onChange={handleChange}
            leadingElement={<Icon src={FavoriteBorder} />}
            floatingLabel="What is your phone number?"
          />
        </Form.Group>
      </>
    ),
    creditCard: (<>
      <h3>Credit card</h3>
      <Form.Group>
        <Form.Control
          inputMask="0000 0000 0000 0000"
          value={value}
          onChange={handleChange}
          leadingElement={<Icon src={FavoriteBorder} />}
          floatingLabel="What is your credit card number?"
        />
      </Form.Group>
    </>),
    securePassword: (<>
      <h3>Secure password</h3>
      <Form.Group>
        <Form.Control
          inputMask="XXX-XX-0000"
          value={value}
          definitions={{
            X: {
              mask: '0',
              displayChar: 'X',
              placeholderChar: '#',
            },
          }}
          onChange={handleChange}
          leadingElement={<Icon src={FavoriteBorder} />}
          floatingLabel="What is your password?"
        />
      </Form.Group>
    </>),
    OTPpassword: (<>
      <h3>OTP password</h3>
      <Form.Group>
        <Form.Control
          inputMask="G-00000"
          value={value}
          onChange={handleChange}
          leadingElement={<Icon src={FavoriteBorder} />}
          floatingLabel="What is your OPT password?"
        />
      </Form.Group>
    </>),
    price: (
        <>
          <h3>Course priсe</h3>
          <Form.Group>
            <Form.Control
              inputMask="$num"
              blocks={{
                num: {
                  // nested masks are available!
                  mask: Number,
                  thousandsSeparator: ' '
                }
              }}
              value={value}
              onChange={handleChange}
              leadingElement={<Icon src={FavoriteBorder} />}
              floatingLabel="What is the price of this course?"

    </>
  );
}
```

## Input masks with clear value
To get a value without a mask, you need to use `onChange` instead of `onAccept` to handle changes.

```jsx live
() => {
  const [value, setValue] = useState('');

  return (
      <>
        <Form.Group>
          <Form.Control
            inputMask="+{1} (000) 000-0000"
            leadingElement={<Icon src={FavoriteBorder} />}
            trailingElement={<Icon src={Verified} />}
            floatingLabel="What is your phone number?"
            value={value}
            // depending on prop above first argument is
            // `value` if `unmask=false`,
            // `unmaskedValue` if `unmask=true`,
            // `typedValue` if `unmask='typed'`
            onAccept={(_, mask) => setValue(mask._unmaskedValue)}
          />
        </Form.Group>
        Unmasked value: {JSON.stringify(value)}
      </>
  );
}
```

## Textarea autoResize

`autoResize` prop allows input to be resized according to the content height.

```jsx live
<Form.Control
  as="textarea"
  autoResize
  floatingLabel="Write something long"
/>
```

## Validation

```jsx live
() => {
  const [value, setValue] = useState('');
  const handleChange = (e) => setValue(e.target.value);
  return (
    <>
      <Form.Group>
        <FormLabel>What kind of cats?</FormLabel>
        <Form.Control value={value} onChange={handleChange} />
      </Form.Group>

      <Form.Group isInvalid>
        <FormLabel>What kind of cats?</FormLabel>
        <Form.Control value={value} onChange={handleChange} />
      </Form.Group>

      <Form.Group isValid>
        <FormLabel>What kind of cats?</FormLabel>
        <Form.Control value={value} onChange={handleChange} />
      </Form.Group>
    </>
  );
}
```

## Accessibility

**Status:** documented from source (Paragon 23.x, August 2026). Assistive technology verification pending — see the [Accessibility policy](/guides/accessibility-policy).

`Form.Control` renders a native `<input>` (or `<textarea>` / `<select>` via `as`) through
React-Bootstrap 1.6.5. No [APG pattern](https://www.w3.org/WAI/ARIA/apg/patterns/) applies — native
HTML form semantics carry the interaction. Inside a `Form.Group`, the control receives its `id` and
`aria-describedby` wiring from the group context.

### Keyboard support

All keyboard interaction is the native behavior of the rendered element: text editing for
`input`/`textarea`, <kbd>Arrow Up</kbd>/<kbd>Arrow Down</kbd> option navigation for `as="select"`,
and so on. Paragon adds no custom key handling; `autoResize` and `inputMask` change what is
displayed, not how keys behave.

### ARIA roles, states, and properties

| Element | Attribute | Notes |
| --- | --- | --- |
| Control | `id` = the group's `controlId` | Provided by `FormGroupContext`; this is what `Form.Label`'s `htmlFor` targets. |
| Control | `aria-describedby` | The id of every `Form.Control.Feedback` in the group, merged with any `aria-describedby` you pass yourself. |
| Control with `isValid` / `isInvalid` | *(classes only)* | Renders `is-valid` / `is-invalid` styling classes (provided by React-Bootstrap); `aria-invalid` is **not** set — see Known issues. |
| Floating label (`floatingLabel`) | `<label>` with `htmlFor` = `controlId` | A real label element, so the floating label is the control's accessible name. |
| `leadingElement` / `trailingElement` | *(none)* | Rendered in plain decorative `<div>`s; Paragon `Icon`s placed there default to `aria-hidden="true"`. |

### Screen reader expectations

- On focus, the control announces its label (from `Form.Label` or `floatingLabel`), its role
  ("edit text", "combo box", ...), the current value, and the feedback text via `aria-describedby`.
  *(Verification pending per the policy's AT matrix.)*
- Leading and trailing icon decorators are silent (`aria-hidden`) unless you label them.
- An invalid state is not announced on its own (no `aria-invalid`; see Known issues).

### Application responsibilities

- Use `Form.Control` inside a `Form.Group`; outside one, no `id` or `aria-describedby` is
  generated and you must wire up a label yourself.
- Provide exactly one accessible name: a `Form.Label`, a `floatingLabel`, or (last resort) an
  `aria-label`. `placeholder` is not a label.
- With `inputMask`, describe the expected format in the label or a `Form.Control.Feedback` — the
  mask silently reformats the value as the user types.
- If a `trailingElement` is interactive (e.g. an `IconButton`), give it an accessible name and
  confirm it is reachable with <kbd>Tab</kbd>.
- Set `autocomplete` on fields that collect personal data (WCAG 1.3.5).

### Relevant ACT rules

[W3C Accessibility Conformance Testing rules](https://www.w3.org/WAI/standards-guidelines/act/rules/)
give objective, tool-neutral procedures for testing the claims above:

- [Form field has non-empty accessible name](https://www.w3.org/WAI/standards-guidelines/act/rules/e086e5/) — via `Form.Label`, `floatingLabel`, or `aria-label`
- [Autocomplete attribute has valid value](https://www.w3.org/WAI/standards-guidelines/act/rules/73f2c2/)
- [ARIA state or property has valid value](https://www.w3.org/WAI/standards-guidelines/act/rules/6a7281/) — `aria-describedby` must reference rendered ids
- [Element in sequential focus order has visible focus](https://www.w3.org/WAI/standards-guidelines/act/rules/oj04fd/)

### Known issues

- `isInvalid` (own prop or inherited from the group) only adds the `is-invalid` styling class;
  `aria-invalid="true"` is not rendered, so assistive technology is not told the field is in an
  error state — identified in the August 2026 accessibility audit.
