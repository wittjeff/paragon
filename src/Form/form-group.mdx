`Form.Group` provides its children a context that contains ids and attributes
that enable these components to relate to each other according to WCAG guidelines.

`Form.Group` renders a `FormGroupContextProvider` which will autogenerate a
controlId if none is supplied and offers `size`, `isInvalid`, `isValid` in the
context. `Form.Control`, `Form.Label`, and `Form.Control.Feedback` consume this context.

## Basic Usage

```jsx live
  <Form.Group
    isInvalid
    controlId="explicit-id-1"
  >
    <Form.Label>What kind of cats?</Form.Label>
    <Form.Control />
    <Form.Control.Feedback type="invalid">You are incorrect!</Form.Control.Feedback>
  </Form.Group>
```

```jsx live
  <Form.Group
    isValid
    controlId="explicit-id-2"
  >
    <Form.Label>What kind of cats?</Form.Label>
    <Form.Control />
    <Form.Control.Feedback type="valid">You are correct!</Form.Control.Feedback>
  </Form.Group>
```

## Sizes

```jsx live
() => {
  const [value, setValue] = useState('');
  const handleChange = (e) => setValue(e.target.value);
  return (
    <>
      <Form.Group size="sm">
        <Form.Label>What kind of cats?</Form.Label>
        <Form.Control
          value={value}
          onChange={handleChange}
        />
      </Form.Group>

      <Form.Group>
        <Form.Label>What kind of cats?</Form.Label>
        <Form.Control
          value={value}
          onChange={handleChange}
        />
      </Form.Group>

      <Form.Group size="lg">
        <Form.Label>What kind of cats?</Form.Label>
        <Form.Control
          value={value}
          onChange={handleChange}
        />
      </Form.Group>
    </>
  );
}
```

## Accessibility

**Status:** documented from source (Paragon 23.x, August 2026). Assistive technology verification pending — see the [Accessibility policy](/guides/accessibility-policy).

`Form.Group` renders a plain `<div>` (configurable via `as`) with no ARIA of its own. Its
accessibility role is indirect: through `FormGroupContext` it generates and distributes the ids
that associate label, control, and feedback. No
[APG pattern](https://www.w3.org/WAI/ARIA/apg/patterns/) applies.

### Keyboard support

`Form.Group` renders static structure and has no keyboard interaction of its own.

### ARIA roles, states, and properties

The group element itself renders no ARIA attributes. What the context provides to children:

| Child | Receives | Notes |
| --- | --- | --- |
| `Form.Control` | `id` = `controlId` | Your `controlId` prop, or an autogenerated id. |
| `Form.Control` | `aria-describedby` | The id of every `Form.Control.Feedback` rendered in the group; multiple feedback elements are merged into the list. |
| `Form.Label` | `htmlFor` = `controlId` | Renders a native `<label>` for the control. |
| `Form.Control.Feedback` | `id` | Explicit or autogenerated; registered into the control's `aria-describedby`. |
| Grouped controls (`Form.RadioSet`, `Form.CheckboxSet`) | `aria-labelledby` = label id | The set registers itself as a control group; `Form.Label` then renders as `<p id="...">` instead of `<label>`, and the set's `role="radiogroup"` / `role="group"` element points at it. |

`isInvalid` / `isValid` on the group flow to the control and feedback as styling state only — see
Form.Control's Known issues for the missing `aria-invalid`.

### Screen reader expectations

- Focusing the contained control announces its label and, via `aria-describedby`, each feedback
  text in the group. *(Verification pending per the policy's AT matrix.)*

### Application responsibilities

- Use one `Form.Group` per field (or per radio/checkbox set) — the context carries a single
  `controlId`, so multiple controls in one group would share the same id.
- Always include a `Form.Label` (or a `floatingLabel` on the control) inside the group.
- Pass an explicit `controlId` when you need stable ids (external labels, deep links, testing);
  otherwise ids are autogenerated.

### Relevant ACT rules

[W3C Accessibility Conformance Testing rules](https://www.w3.org/WAI/standards-guidelines/act/rules/)
give objective, tool-neutral procedures for testing the claims above:

- [Form field has non-empty accessible name](https://www.w3.org/WAI/standards-guidelines/act/rules/e086e5/) — the group's wiring is what gives the field its name
- [ARIA state or property has valid value](https://www.w3.org/WAI/standards-guidelines/act/rules/6a7281/) — generated `aria-describedby` / `aria-labelledby` values must reference rendered ids

### Known issues

No `Form.Group`-specific issues were identified in the August 2026 accessibility audit. The missing
`aria-invalid` when a group is marked `isInvalid` is documented under Form.Control.
