A switch control for use with `Form.SwitchSet`. This component has identical
props to `Form.Checkbox` and is interoperable with `Form.SwitchSet` and
`useCheckboxSetValues`.

Note: extra props added to this component are passed as attributes to the
underlying `input` node. See MDN for documentation on available
[input attributes](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attributes).


## Controlled Standalone Usage

```jsx live
() => {
  const [isChecked, setChecked] = useState(false);
  const handleChange = e => setChecked(e.target.checked);
  return (
    <Form.Switch checked={isChecked} onChange={handleChange}>
      I want pizza.
    </Form.Switch>
  );
}
```

## Unlabeled control

```jsx live
() => {
  const [isChecked, setChecked] = useState(false);
  const handleChange = e => setChecked(e.target.checked);
  return (
    <SwitchControl
      checked={isChecked}
      onChange={handleChange}
      aria-label="Form switch"
    />
  );
}
```

## Controlled Group Usage with useCheckboxSetValues

`useCheckboxSetValues(initialValues[])` returns an array: `[state, dispatchers]`.

`dispatchers` includes `add(value)` `remove(value)` `set(values[])` and `clear()`

```jsx live
() => {

  const [colorValues, { add, remove }] = useCheckboxSetValues(['green']);

  const handleChange = e => {
    if (e.target.checked) {
      add(e.target.value);
    } else {
      remove(e.target.value);
    }
  }
  return (
    <Form.Group>
      <Form.Label>Which Color?</Form.Label>
      <Form.SwitchSet
        name="colors"
        onChange={handleChange}
        value={colorValues}
      >
        <Form.Switch value="red">Red</Form.Switch>
        <Form.Switch value="green">Green</Form.Switch>
        <Form.Switch value="blue">Blue</Form.Switch>
        <Form.Switch value="cyan" disabled>Cyan</Form.Switch>
      </Form.SwitchSet>
    </Form.Group>
  );
}
```

## Indeterminate Usage

```jsx live
() => {
  const allCheeseOptions = ['swiss', 'cheddar', 'pepperjack'];
  const [checkedCheeses, { add, remove, set, clear }] = useCheckboxSetValues(['swiss']);

  const handleChange = e => {
    e.target.checked ? add(e.target.value) : remove(e.target.value);
  };

  const handleCheckAllChange = e => {
    e.target.checked ? set(allCheeseOptions) : clear();
  };

  const allChecked = allCheeseOptions.every(value => checkedCheeses.includes(value));
  const someChecked = allCheeseOptions.some(value => checkedCheeses.includes(value));
  const isIndeterminate = someChecked && !allChecked;

  return (
    <>
      <div className="d-flex">
        <Form.Switch
          checked={allChecked}
          isIndeterminate={isIndeterminate}
          onChange={handleCheckAllChange}
        >
          All the cheese
        </Form.Switch>
      </div>
      <Form.SwitchSet
        className="p-2"
        value={checkedCheeses}
        onChange={handleChange}
      >
        <Form.Switch value="swiss">Swiss</Form.Switch>
        <Form.Switch value="cheddar">Cheddar</Form.Switch>
        <Form.Switch value="pepperjack">Pepperjack</Form.Switch>
      </Form.SwitchSet>
    </>
  );
}
```

## Label Position

The label is positioned to the right of the switch control by default. The label can be rendered on the left instead
by passing the `floatLabelLeft` prop.

```jsx live
<Form.Group>
  <Form.SwitchSet>
    <Form.Switch value="red">Red</Form.Switch>
    <Form.Switch value="blue" floatLabelLeft>Blue</Form.Switch>
  </Form.SwitchSet>
</Form.Group>
```

## Helper Text

A helper text component can be passed in to be rendered below the switch control.

```jsx live
<Form.Group>
  <Form.SwitchSet>
    <Form.Switch
      value="red"
      helperText={
        <span>Helper text for red switch</span>
      }
    >
      Red
    </Form.Switch>
    <Form.Switch
      value="blue"
      helperText={
        <span>Helper text for blue switch</span>
      }
    >
      Blue
    </Form.Switch>
  </Form.SwitchSet>
</Form.Group>
```

## Accessibility

**Status:** documented from source (Paragon 23.x, August 2026). Assistive technology verification pending — see the [Accessibility policy](/guides/accessibility-policy).

`Form.Switch` renders a native `<input type="checkbox">` with `role="switch"`, following the
[APG switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/): native checkbox keyboard
behavior with switch (on/off) semantics.

### Keyboard support

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd> | Moves focus to the next / previous switch; each switch is its own tab stop. |
| <kbd>Space</kbd> | Toggles the focused switch (native checkbox activation). |

Paragon adds no JavaScript key handling; all keyboard behavior is native.

### ARIA roles, states, and properties

| Element | Attribute | Notes |
| --- | --- | --- |
| Control | `<input type="checkbox">` with `role="switch"` | Covered by unit tests. The native checked state conveys on/off. |
| Control | `id` | Uses the `id` prop, or an auto-generated `form-field-*` id. |
| Label (`<label>`) | `for` = control id | The `children` of `Form.Switch` are the switch's accessible name. |
| `helperText` (`<div>`) | *(no association)* | Rendered below the switch but **not** referenced by `aria-describedby` — see Known issues. |
| `Form.SwitchSet` container (`<div>`) | `role="group"` + `aria-labelledby` | `Form.SwitchSet` is the same component as `Form.CheckboxSet`. |

Unlike `Form.Checkbox`, the `isValid`, `isInvalid`, and `description` props are deliberately
ignored by `Form.Switch`.

### Screen reader expectations

- A focused switch announces its label, "switch", and on/off state — e.g. "I want pizza, switch,
  off". Some screen reader/browser pairings still announce role "checkbox"; this is exactly what
  the policy's AT verification pass will record. *(Verification pending per the policy's AT
  matrix.)*
- `helperText` is not announced when the switch receives focus, because it is not programmatically
  associated (see Known issues).

### Application responsibilities

- Always provide label `children`; when using the bare `SwitchControl`, supply `aria-label` (as the
  example above does).
- Until the `helperText` association gap is fixed, put text a user must hear in the label itself,
  or associate your own element via `aria-describedby`.
- Avoid `isIndeterminate` with switches: `role="switch"` has no mixed state (see Known issues).
- Switches imply an immediate effect when toggled. If the change only applies after a form submit,
  use `Form.Checkbox` instead so semantics match behavior.

### Relevant ACT rules

[W3C Accessibility Conformance Testing rules](https://www.w3.org/WAI/standards-guidelines/act/rules/)
give objective, tool-neutral procedures for testing the claims above:

- [Form field has non-empty accessible name](https://www.w3.org/WAI/standards-guidelines/act/rules/e086e5/) — each switch, and bare `SwitchControl` usage
- [Element with role attribute has required states and properties](https://www.w3.org/WAI/standards-guidelines/act/rules/4e8ab6/) — `switch` requires a checked state (supplied natively by the checkbox)
- [ARIA state or property has valid value](https://www.w3.org/WAI/standards-guidelines/act/rules/6a7281/)
- [Element in sequential focus order has visible focus](https://www.w3.org/WAI/standards-guidelines/act/rules/oj04fd/)

### Known issues

Identified in the August 2026 accessibility audit (code-verified, not yet filed):

- `helperText` is rendered as a plain `<div>` with no id and no `aria-describedby` association, so
  assistive technology users do not hear it in the context of the switch.
- The "Indeterminate Usage" example works visually, but `role="switch"` does not support a mixed
  state — assistive technology reports an indeterminate switch as simply off. Use a checkbox when
  a mixed state is meaningful.
